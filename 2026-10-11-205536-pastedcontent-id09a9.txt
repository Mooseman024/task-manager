     Add optional priority field to tasks

     Context

     Tasks currently have no priority field. We want to add an optional integer
     priority (1=urgent .. 5=low, default 3) so tasks can be ranked. This must
     follow the existing patterns in services/users.py (type hints, Google-style
     docstrings, ValidationError/NotFoundError usage) and the CLAUDE.md
     constraints (no touching utils/errors.py, no reordering/removing existing
     params, routes stay HTTP-only).

     Workflow (TDD)

     1. First, add the new tests to tests/test_tasks.py (described below)
        against
        the current code — before touching services/tasks.py or routes/api.py.
     2. Run pytest -q and show that the new tests fail (since priority support
        doesn't exist yet).
     3. Only then implement the services/tasks.py and routes/api.py changes.
     4. Run pytest -q again and confirm everything passes.

     Changes

     services/tasks.py

     - Add "priority": 3 to each of the three existing TASKS records.
     - Update create_task:
       - New signature: def create_task(title: str, user_id: int, priority: int 
         = 3) -> dict:
         (new param is a keyword-defaulted addition after existing params —
         complies
         with "do not reorder/remove" rule).
       - Validate priority: if not an int (explicitly reject bool, since bool
         is a subclass of int in Python — check isinstance(priority, bool) or 
         not isinstance(priority, int)) or not in range 1-5, raise
         ValidationError("priority", "must be an integer between 1 and 5").
       - Include "priority": priority in the new task dict.
       - Add a Google-style docstring (Args/Returns/Raises) matching get_user's
         style,
         documenting the new ValidationError case.
     - Import ValidationError from utils.errors (not currently imported in this
       file).

     routes/api.py

     - In create_task_route, read optional "priority" from the JSON body
       (default 3)
       and pass it through to create_task, e.g.
       create_task(data["title"], data["user_id"], priority=data.get("priority",
       3)).
       No business-logic validation here — that stays in the service per
       CLAUDE.md.

     tests/test_tasks.py

     - Add tests (new file if it doesn't exist, else append), written and run
       before implementation per the TDD workflow above, covering:
       - create_task defaults priority to 3 when omitted.
       - create_task accepts a valid explicit priority (e.g. 1 or 5).
       - create_task raises ValidationError for out-of-range (e.g. 0, 6) and
         non-integer priority values.
       - create_task raises ValidationError when priority is True/False
         (booleans must be rejected even though bool is an int subclass).
     - Do not modify/weaken any existing tests.

     Verification

     - Run pytest -q before implementation and confirm the new tests fail.
     - Implement the changes, then run pytest -q again and confirm all tests
       pass, including the new priority tests.
     - Optionally run python app.py and POST to /api/tasks with and without a
       priority field to manually confirm behavior.
