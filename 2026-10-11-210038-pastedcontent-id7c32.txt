     Context

     Need a way to update a task's priority via the API. Currently only creation
     sets priority; there's no update path. Add PATCH /tasks/<int:task_id>
     backed by a new update_task service function, following existing
     conventions in the codebase (validation, error handling, docstrings).

     Plan

     services/tasks.py

     Add a private helper _validate_priority(priority: int) -> None:
     - Contains the existing check:
       if isinstance(priority, bool) or not isinstance(priority, int) or not (1 
       <= priority <= 5): raise ValidationError("priority", "must be an integer 
       between 1 and 5")
     - Call this helper from create_task (replacing its inline check) and from
       update_task.

     Add update_task(task_id: int, data: dict) -> dict:
     - Look up task in TASKS; if missing, raise NotFoundError("Task").
     - Reject unknown fields: if data contains any key other than "priority",
       raise ValidationError(<field>, "unknown field") for the first unexpected
       key found.
     - Require "priority" to be present: if missing, raise
       ValidationError("priority", "is required").
     - Call _validate_priority(data["priority"]).
     - Set task["priority"] = data["priority"] and return the updated task dict.
     - Add Google-style docstring (Args, Returns, Raises) matching
       create_task/get_user style.
     - Import NotFoundError alongside ValidationError at the top of the file.
     - No changes to existing function signatures; update_task is new so it can
       take data: dict as its parameter shape (keeps validation logic in
       services, not routes).

     routes/api.py

     Add route:
     @api.route("/tasks/<int:task_id>", methods=["PATCH"])
     def update_task_route(task_id):
         data = request.get_json()
         return jsonify(update_task(task_id, data))
     Update the import line to include update_task from services.tasks. Routes
     stay HTTP-only — no field validation here, all of it happens in
     update_task.

     tests/test_tasks.py

     Add unit tests for update_task:
     - Successfully updates priority and returns updated task.
     - Raises NotFoundError for unknown task id.
     - Raises ValidationError for invalid priority (e.g., 0, 6, "high", True).
     - Raises ValidationError when priority is missing from data.
     - Raises ValidationError when an unknown field is present.

     Do not modify or weaken existing tests.

     Also add route-level tests in tests/test_tasks.py (per CLAUDE.md: one test
     file per service — keep task-related route tests here, not in a separate
     file) using app.test_client() (from app.py):
     - PATCH /tasks/<id> with valid {"priority": N} → 200, response reflects
       updated priority.
     - PATCH /tasks/<id> with an unknown field (e.g., {"title": "x"} or
       {"priority": 2, "extra": 1}) → 422.
     - PATCH /tasks/<id> with missing priority (e.g., {}) → 422.
     - PATCH /tasks/<unknown_id> with valid body → 404.

     Verification

     Run pytest -q and confirm all tests pass, including new ones.
